# Local API (SQLite Backend)

In self-hosted web mode, Siftly uses a local Node.js API backed by SQLite.

- Runtime entrypoint: `server/index.mjs`
- Default API base: `/api`
- Default database file: `data/siftly.db`
- User scope mechanism: `X-User-Id` request header

## Route Summary

| Method | Route                     | Header required | Purpose                                               |
| ------ | ------------------------- | --------------- | ----------------------------------------------------- |
| GET    | `/api/profiles`           | No              | List all local profiles                               |
| POST   | `/api/profiles`           | No              | Create or update a local profile                      |
| DELETE | `/api/profiles/:id`       | No              | Delete profile and cascade delete local apps/settings |
| GET    | `/api/profile`            | No              | Compatibility route returning the latest profile      |
| GET    | `/api/applications`       | `X-User-Id`     | List applications for one profile                     |
| POST   | `/api/applications`       | `X-User-Id`     | Upsert one application                                |
| DELETE | `/api/applications`       | `X-User-Id`     | Delete all applications for one profile               |
| POST   | `/api/applications/batch` | `X-User-Id`     | Batch upsert applications                             |
| DELETE | `/api/applications/:id`   | `X-User-Id`     | Delete one application by id for one profile          |
| GET    | `/api/settings`           | `X-User-Id`     | Read settings snapshot for one profile                |
| POST   | `/api/settings`           | `X-User-Id`     | Upsert settings snapshot for one profile              |

## Error Behavior

- `401`: missing `X-User-Id` on user-scoped routes
- `409`: profile conflict on unique display name or email
- `400`: malformed profile delete route without id
- `404`: unknown API route
- `500`: internal errors, including malformed JSON payloads

## Request Notes

### Profile payload

```json
{
  "id": "local-123",
  "displayName": "Piero",
  "email": "piero@example.com",
  "avatarUrl": null
}
```

### Application payload

The API stores application payloads as JSON in SQLite and returns the same structure on reads. Use the `JobApplication` shape from `src/types/job.ts`.

### Settings payload

Settings are persisted as a single JSON snapshot per profile (`settings.user_id` primary key). The backend accepts full snapshots generated by `src/lib/settingsStorage.ts`.

## cURL Examples

```bash
curl -X POST http://localhost:8080/api/profiles \
  -H 'Content-Type: application/json' \
  -d '{"id":"local-1","displayName":"Piero"}'
```

```bash
curl http://localhost:8080/api/applications \
  -H 'X-User-Id: local-1'
```

```bash
curl -X POST http://localhost:8080/api/settings \
  -H 'Content-Type: application/json' \
  -H 'X-User-Id: local-1' \
  -d '{"language":"en","currency":"USD"}'
```
