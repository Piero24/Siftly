# Versioning and Releases

This page defines the official Siftly release flow for alpha, beta, rc, and stable versions.

## Canonical Release Flow

Siftly now uses **Release Please** as the release entrypoint.

1. Merge Conventional Commit PRs into `main`.
2. `release-please.yml` opens or updates a release PR.
3. Review and merge the release PR.
4. Release Please creates a `v*` tag and GitHub Release.
5. Tag-triggered workflows publish extension and Docker artifacts.

Normal flow: no manual version edits in multiple files and no manual tag creation.

## Single Source of Truth for Version

Version starts in `metadata.json` (`version`).

`npm run metadata:sync` propagates that version into:

- `package.json`
- `public/manifest.json`
- `documentation/package.json`
- `README.md` version badge

CI and release workflows run `npm run metadata:verify` to prevent drift.

## Supported Version Formats

Use SemVer with prerelease identifiers:

- Alpha: `1.2.0-alpha.1`
- Beta: `1.2.0-beta.1`
- RC: `1.2.0-rc.1`
- Stable production: `1.2.0`

## Tag Format

Tags are `v` + release version and are generated by Release Please:

- `v1.2.0-alpha.1`
- `v1.2.0-beta.1`
- `v1.2.0-rc.1`
- `v1.2.0`

## Outcome Matrix

| Version kind      | Example version | Example tag     | GitHub Release  | Chrome Web Store | Docker deploy |
| ----------------- | --------------- | --------------- | --------------- | ---------------- | ------------- |
| Alpha/Beta/RC/Dev | `1.2.0-beta.1`  | `v1.2.0-beta.1` | Prerelease      | Skipped          | Runs          |
| Stable            | `1.2.0`         | `v1.2.0`        | Regular release | Published        | Runs          |

Prerelease detection for extension publish still checks `package.json` version content (`alpha`, `beta`, `rc`, `dev`), which remains synced from `metadata.json`.

## Contributor Checklist

When changing release-related metadata:

1. Edit `metadata.json`.
2. Run:

```bash
npm run metadata:sync
npm run metadata:verify
```

3. Commit using Conventional Commits.
4. Merge to `main`.
5. Merge the generated release PR when ready.

## Emergency / Manual Release Path

Manual tag-based release is still technically possible (because downstream workflows trigger on tags), but it is not the standard process and should be used only for emergency recovery.

If used, ensure metadata is synced first:

```bash
npm run metadata:verify
```
